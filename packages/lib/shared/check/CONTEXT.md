# check

The checker is the security boundary of the product: everything the Snap and the website show comes from here. It trusts nothing from Arkiv, from record values or from the caller except the pins. Every chain read in one `checkTargets` call is pinned to one Sepolia block: `deps.block`, or the head minus `deps.headLag` (default 2 blocks, 0 on Anvil, detected with `web3_clientVersion`, because load-balanced public RPCs lag each other).

## Flow per target (`index.ts` → `publisherVerdict.ts` → `evaluate.ts`)

1. **Candidates.** Pinned path: the publisher's `PubRegistry` and root come from walking the registries (`getSubregistry` from `ROOT_REGISTRY` down to the parent, `getOwner` of the name's token); a pin whose stored `PubRegistry` differs is a pinned MISMATCH (critical) until re-confirmed. For every key in `codemark.keys` that is still mounted, the candidate is `a-<12 hex>.<key>.<publisher>`. Open path: Arkiv `findReleases(artifact)`; `findIncidentsByArtifact` for pulls.
   Each publisher is checked in its own `try`: an unpinned publisher whose reads throw (e.g. an attacker row naming `p.evil.eth` whose registry reverts) is dropped and listed in `skippedPublishers`; a pinned one becomes a critical MISMATCH. Registry reads on addresses taken from rows treat reverts and empty return data as "not found".

The publisher's `PubRegistry` must give every root role except `ROLE_UNREGISTER` to root alone, otherwise MISMATCH (someone could relink keys).

2. **Row authentication** (`rows.ts`, `publisherVerdict.ts`). `$creator == $owner`, created read-only, name equals `<label>.<keyLabel>.<publisher>` with a matching `labelhash`, `regBlock >= resolverBlock`, `$creator` has root `ROLE_REGISTRAR` on `row.keyRegistry`, and that registry is the live `PubRegistry.getSubregistry(keyLabel)` or one an authenticated cut incident proves was linked. Anything else is dropped silently.
3. **Name binding** (`binding.ts`, `evaluate.ts`). `UR.findResolver(N)` must return a non-zero resolver at offset 0 (the deployed UR returns resolver 0, offset 0 for names that do not exist). The live `PubRegistry.getSubregistry(key)` must be the candidate's key registry, `KeyRegistry.getResolver(label)` must equal the UR's resolver and `getSubregistry(label)` must be 0. `text("codemark")` and `addr(0x80aa36a7)` are read through `UR.resolve`, whose returned resolver must match. An address record that is not the target means "no claim" (never MISMATCH, so a row cannot make a publisher dispute an address it never named). The label must be `<n>-<maj>-<min>-<patch>` (`versionLabel`) or the forward label. The target must have code that is not an EIP-7702 delegation designator (`0xef0100…`, whose code can change), the EIP-1967 beacon slot must be empty (beacon proxies are not attested), and `keccak(getCode(target))` must equal `h`; if the EIP-1967 slot is set or `i` is present, both must match and `ih` must be the implementation's code hash. `k=web` never matches an address; a `delegation` target needs `k=delegate`; any `k=delegate` needs root to be the only `ROLE_REGISTRAR` holder on the key registry.
4. **Immutability** (`proof.ts`). Checks that need no block numbers (`staticProof`) always run, also for VERIFIED-unproven: `VerifiableFactory.verifyContract(resolver)` returns the current implementation and reverts on non-proxies (revert = MISMATCH); it must be `PermissionedResolverImpl`. The log checks (`proveFromLogs`) need the two blocks: VF must have emitted `ProxyDeployed(proxyAddress = resolver, implementation = PermissionedResolverImpl)` at `resolverBlock`; that log's transaction is the creation transaction. From `resolverBlock` to the pinned block the resolver may emit logs only in the creation transaction, with exactly one `Upgraded(PermissionedResolverImpl)`. This is stricter than listing record and role events: any later log (record, `Linked`, `EACRolesChanged`, `ResourceArgument`, upgrade) fails. Resolver root roles: `roleCount(0)` must equal `roles(0, root)` (every root role held once, by root). `roleCount` must be 0 on `resource(0x80aa36a7)`, `resource(0x80000000)` and `resource("codemark")`. On the key registry, every root role except `ROLE_REGISTRAR`, `ROLE_UNREGISTER` and `ROLE_RENEW` must be held by root alone (otherwise a CI key with `ROLE_SET_RESOLVER` could swap resolvers). Each release label used (the resolved one and the row's) must be owned by root with `roleCount(label) == 0`, which also rejects promoted reserved labels (`ROLE_WAS_RESERVED`), and the low 32 bits of `getTokenId(labelId)` (the token version, see `LibLabel.withVersion`) must be 0. The version is bumped by every `unregister` of a registered token, every re-registration over an expired token and every role grant or revoke on it, so a nonzero version means the label was pulled, lapsed or regenerated before: a CI key reviving a pulled name with its old, clean resolver is MISMATCH even if the pull incident never reaches the checker. The cost: a release label can never be legitimately reused. No non-root account the checker can name (the `LabelRegistered` sender at `regBlock`, every authenticated row creator for the key registry) may hold both `ROLE_REGISTRAR` and `ROLE_UNREGISTER` on it; otherwise MISMATCH. Holders cannot be enumerated from role counts alone, so a dual-role key that neither registered this release nor wrote a row is not seen. Without `resolverBlock`/`regBlock` (no authenticated row, nothing cached) a non-delegate is VERIFIED-unproven. Delegates have no rows: their blocks come from a backward chunked scan of the key registry for `LabelRegistered(labelHash)` whose token is the current one and whose sender is root, then of VF `ProxyDeployed(proxyAddress)`. No such registration is MISMATCH.
5. **Age.** `eth_getLogs` on the key registry for `regBlock` alone must contain `LabelRegistered` whose `tokenId` is the current `getTokenId(labelId)`. Age is the pinned block's timestamp minus `regBlock`'s timestamp, not wall-clock time, so an Anvil fork warped forward ages releases consistently. `deps.now` is not used for ages.
6. **Incidents** (`incidents.ts`). Same row rules, and `$creator` must hold root `ROLE_UNREGISTER` on the live `PubRegistry`. The `ensTx` receipt must have succeeded at exactly `block` (≤ pinned block) and contain `LabelUnregistered` from the right registry: for a pull, from `row.keyRegistry` (which must be live under the key named in `row.name`) for the artifact's forward label; for a cut, from the `PubRegistry` for a token whose label (version bits ignored) is the one `SubregistryUpdated(tokenId, subregistry = keyRegistry)` logged at `linkBlock`. A cut key is KEY REVOKED even if it resolves again, but only for artifacts its detached registry still names (`getResolver(label)` non-zero and the resolver's address record equals the target, tried for the forward label and every authenticated row label). Cut incidents are read with up to `maxIndexPages` pages; a flooded, incomplete or failed incident query sets `indexIncomplete` but does not downgrade a pinned result, because anyone can write incident rows (it would be a free denial of service on the pinned path) and a hidden cut or pull cannot produce green: a cut unlinks the key registry, so its names stop resolving (UNKNOWN), and a revived pulled name fails the token-version check. Receipt lookups return "not found" only for `TransactionReceiptNotFoundError`; other RPC errors propagate. A release that still resolves after an authenticated pull of its forward label is MISMATCH. `reason` is untrusted text: control and bidi characters are stripped, 280 characters at most.
7. **Verdicts and severity** (`severity.ts`). Per publisher the best candidate wins (VERIFIED, VERIFIED-unproven, KEY REVOKED, PULLED, MISMATCH). A pinned KEY REVOKED, PULLED or MISMATCH is critical. `delegation` and `delegatecall` targets must be `k=delegate` releases under a key where root is the sole registrar, so a CI key can never publish code that runs with the signer's authority. For those targets anything but a pinned, proven VERIFIED at least `delegateMinAgeSeconds` old is critical. For other roles: pinned proven VERIFIED younger than `freshCallAgeSeconds` is amber, older is info; pinned unproven, unpinned ("vouched for" / "disputed by") and UNKNOWN are warnings. A flooded, incomplete or unreachable index never turns anything green. An exception while checking a target gives a warning (critical for delegation/delegatecall) with `error` set.

## Display names

`ReleaseInfo.name` is the version name (`<n>-<maj>-<min>-<patch>.<key>.<publisher>`) when the key registry gives that label the same resolver, otherwise the name that was resolved; `forwardName` is the `a-<12 hex>` name when it is bound to the same resolver.

## Caching

`deps.cache` (JSON values; bigints stored as decimal strings, keys prefixed `codemark:v1:`) holds: per-resolver log scans (`resolver:<addr>`, extended incrementally), proven block pairs per key registry, label and resolver (`blocks:…`, so the pinned path stays proven when Arkiv is down), delegate block pairs (`delegate:…`), and authenticated cut incidents per pinned publisher and registry (`cuts:<name>:<pubRegistry>`), so KEY REVOKED survives the key leaving `codemark.keys` and Arkiv going down. Cached values are only hints for block numbers or already-authenticated incidents; every on-chain condition is re-read at the pinned block.

The per-resolver scan is cached only up to the pinned block minus 12 blocks; the tail is rescanned on every check, so a lagging node that omits recent logs cannot advance the cache past them. Log requests that fail are split in halves down to 256 blocks before giving up (forked and pruned RPCs cap ranges), and backward scans start with a 1 024-block window that doubles up to the chunk size.

Log scans are chunked by `deps.logChunkBlocks` (default 49 000, under the 50 000-block cap most providers set) and backward scans stop after `deps.scanDepthBlocks` (default 1.5 M blocks).

**Limits.** A request has a deadline (`timeoutMs`, 20 s). Delegation and delegatecall targets are checked first, at most `maxTargets` (32) targets are checked, and each target evaluates its pins plus at most `maxUnpinnedPublishers` (8) names from the index; the rest are listed as skipped. Anything not reached gets `error` set and is critical for delegation and delegatecall targets, a warning otherwise, so a flooded index or an oversized batch cannot time the Snap out into showing nothing. A failed read is dropped from the per-request memo, so one RPC error does not repeat across every target.
